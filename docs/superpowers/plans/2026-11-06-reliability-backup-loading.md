# 音源、个人备份与加载优化实施计划

用户已批准上一轮建议，本轮执行其中优先的三项，沿用原生前端、静态曲库与现有代理。

- [x] 音源主备。保留可信搜索候选及已核实的静态音源，试听和答题共用恢复逻辑。仅对有歌曲及歌手或番剧证据的候选建立备用，尊重来源限制与失败排除。失败记录展示时间、来源与原因。
- [x] 个人备份。新增无依赖的 `personal-backup.mjs`，只备份白名单个人数据，不包含媒体缓存、Firebase 身份或凭据。JSON 校验完成后展示恢复摘要，用户确认后覆盖备份包含的数据，写入失败回滚。兼容旧歌曲数组导入，保留已知番剧、封面与音源字段。
- [x] 下一题预查。新增 `audio-prefetch.mjs` 管理最多一首延后解析任务，仅在单人当前歌曲播放成功后预查下一题，不创建播放器、不提前播放。离开页面、回顾、来源改变或挑战结束时取消请求；进入下一题接管解析结果。数据节省模式禁用预查。
- [x] 验证。先添加并运行失败回归测试，再实施。运行全套 Node 测试、曲库校验、完整性审计与语法检查。在 8080 实测备份恢复、试听、答题、下一题和手机布局。实际网络耗时只报告观察结果。
- [x] 文档。按最终实现更新 README 与 PROJECT_STATUS，记录第三方音源及未覆盖测试的边界。保留工作区已有的无关改动，不修改原有歌曲顺序或数据库。

验收重点是同一歌曲试听与答题解析一致，恢复不重复尝试已失败视频，备份可往返且无效文件不会改写本地数据，预查取消不会误操作当前播放器。
