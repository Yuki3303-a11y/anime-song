# 萌豚挑战 · 二次元听歌猜番剧

听一段约30秒的动画歌曲，猜番剧、歌名或歌手。混合模式会逐题切换题型。统一曲库目前有4230个曲目条目，按114个非空季度归档。2011—2019年每年60部番剧，2010年及以前合计100部；各部已核实的OP/ED及后续OP/ED一并收录。原有315首歌曲与2020年1月至2026年10月全部28个季度继续保留。音频由第三方平台实时提供。

## 本地运行

准备 Node.js 22 或 24、可通过 `python` 命令运行的 Python 3，以及现代浏览器。首次运行在仓库目录执行 `npm ci`，安装 Vercel 函数使用的 `spark-md5`。

Windows 双击 **一键启动.bat**。它会启动或复用 8080 网站服务和 8765 B 站代理，再打开浏览器。也可以分别启动：

```sh
python -m http.server 8080 --bind 127.0.0.1
node bili-proxy.mjs
```

打开 [本地网站](http://127.0.0.1:8080/)。通过 HTTP 加载浏览器 ES Modules。B 站代理可单独用 `启动B站代理.bat` 启动。浏览器会尝试探测本地代理，也可在设置中填写 `http://127.0.0.1:8765`。

## 游戏与曲库

- 首页以当前曲库的完整番剧封面和番剧名为主视觉，进入或返回首页时随机起图；封面两侧可切换，同一部番剧的多首歌曲只占一个位置。猜番剧为主按钮，猜歌名、猜歌手与混合模式为小按钮。曲库范围和数量集中在右侧，支持一键应用入门精选、进阶挑战、动漫高手三个热度预设；下方当季海报独立分页，保留完整封面比例。答题后的番剧卡片同样完整显示封面。
- 单人挑战可选 10、20、30 题，实际题数受曲池大小限制。答题后左侧展示番剧和歌曲信息，支持复听、收藏、反馈和回顾。提示会降低本题得分。
- 「我的曲库」分为当前曲库与全部曲库。全部曲库下只有“全部番剧、季度番剧、Bangumi 导入”。原有歌曲归入对应季度，季度面板平铺年份按钮，2010年及以前合并为一个选项，2011年起可筛选01/04/07/10月档。每页24部番剧，曲目可试听、反馈；偏好按整部番剧加入追番。追番与音源反馈收在「曲库工具」。Bangumi导入及歌曲JSON导入导出保留。
- 收藏、排行榜、设置、导入歌曲、追番和音源反馈保存在当前浏览器的 `localStorage`，按站点来源隔离。收藏在首页默认折叠，展开后可播放和管理。
- 设置中的「个人数据备份」可导出和恢复这些记录，以及组合范围和最近出题记录。恢复先显示摘要，确认后恢复并刷新。单曲选歌和错题本已移除；旧选歌一次性迁移为对应番剧的追番，旧备份仍能恢复支持的数据。
- 联机 PK 使用 Firebase 匿名身份和 Realtime Database。房间以四位房间号或邀请链接加入，题目按 `songs.js` 导出的 `PK_SONGS` 稳定索引同步。已移除歌曲的索引留空，剩余歌曲保持原编号；旧房间含已移除曲目时提示重建。

前端采用原生 HTML、CSS、JavaScript 和浏览器 ES Modules。Firebase SDK 通过 CDN 加载。播放使用 HTML Audio 与 YouTube IFrame Player API。本地代理使用 Node 内置模块，Vercel 函数使用 `spark-md5` 生成 B 站 WBI 签名。

曲库显示优先使用大陆授权或国内常用的番名。歌曲已有通行译名时使用通行译名，其余保留发行方使用的日文或拉丁字母写法。歌手以动画使用版本的演唱署名为准。

自带曲库补录了 [小小佐仓千代的 2026 年动漫歌曲 Top 150](https://www.bilibili.com/video/BV1bHZLBiEQx) 中原来缺少的 27 首。按具体作品和录音版本去重，原有歌曲的索引保留。

除用户确认移除的曲目外，历次歌曲均保留。历史扩充数量、候选缺口和来源见 [2020年前扩充复核](candidates/pre2020-expansion-review.md) 与 [季度归档复核](candidates/season-archive-review.md)。同名不同演唱版本有独立记录，追番和旧组合继续有效。自由组合可将追番、多个季度、Bangumi导入取并集。

热度预设使用已发布作品的冻结Bangumi榜单：早期与2011—2019年按年度排名，2020年起按季度排名。入门取早期前10、历史每年前3、每季前2作品的一首已收录OP；进阶扩大为25/10/5，每部取首支已收录OP和ED；高手扩大为60/30/15，取各部已收录OP/ED。当前规模分别为90部/90条、251部/483条、728部/2266条，高手单局去重后2207首。应用预设会清除类型与仅追番筛选，保留原追番、导入、组合和10/20/30题设置；来源以 `preset:beginner/regular/expert` 保存。试听与答题使用同一曲目引用。更新季度时应同步 `preset-ranks.js` 中对应的已发布排名位置。

上述热度来自更新曲库时保存的Bangumi `sort:heat` 排名，不会实时重排，也不是歌曲播放量或玩家正确率。三个预设同时改变作品覆盖范围和每部作品的OP/ED收录深度。主题曲关系、歌名和歌手以AnimeThemes及复核时使用的官方发行资料为依据，详见候选与扩充复核记录。

## 核心数据流

1. 单人出题先合并曲库和筛选范围，按歌名与番剧去重，优先抽取最近五局没出现的歌曲。池子不足时先抽较早出现过的歌曲，抽完再打乱顺序。只记录音源已就绪的题目，有其他歌曲时避开上一局最后出现的歌曲。猜番剧可以查看歌手和首播年份，使用提示会降低本题得分。
2. 音源解析先使用曲目中已确认的 `itunesPreviewUrl`、`youtubeVideoId`、`bilibiliVideoId`，同一首可以保存多个来源。固定 YouTube 候选会先给 iTunes 最多 1.5 秒的精确匹配机会；iTunes 返回第一组已验证候选，不等待其他慢查询。没有可用固定源时，智选三源并行检索 iTunes、YouTube 和 B 站。设置可限定为 iTunes + YouTube 或仅 B 站。搜索使用歌名、番名、歌手、类型和可用别名。视频必须同时具有歌名与番剧或歌手证据，过滤伴奏、纯音乐、无人声、翻奏等错误版本；短英文名采用词边界。B 站在截取备用名单前执行同一过滤，不能用播放量抵消身份不符。YouTube 评分计入嵌入播放成本，可靠 iTunes 预览通常优于同等身份的视频上传。强候选可提前结束收集，普通候选有约 1500ms 的收集窗口，收集阶段硬上限约 8 秒；后续取流与播放器准备另有超时。
3. iTunes 返回试听地址，YouTube 候选检查嵌入状态，B 站先搜视频再取音频流。媒体就绪后开放答题。搜索结果保留最多 8 个同时具备歌曲名及歌手或番剧证据的备用候选。试听与答题恢复时先尝试已有备用，再重新搜索，并排除失败的视频或来源。B 站播放失败会清除对应取流缓存。无可用结果时，单人模式会尝试换歌或跳题，跳过不计错。音源反馈显示本机最近失败的时间、来源和原因。
4. 曲库试听与答题共用音源解析和会话内解析缓存，B 站会话结果有效期为 20 分钟，其他来源为 6 小时。并发请求按歌曲与来源设置合并。B 站视频搜索结果缓存 24 小时，取流结果缓存 30 分钟。两者通过 `MemCache` 写入本地存储，CDN 地址可能提前失效。季度封面来自内置地址，其他封面按需查询并缓存。
5. Bangumi 目录导入优先读取仓库里的同号 JSON，其余目录通过公共 CORS 转发获取 API 或目录页面。随后用 AniList 和 iTunes 补充番名、匹配歌曲并写入本机自定义曲库。
6. 单人歌曲实际播放成功后，延后约 650ms 解析下一题音源。最多保留一个待接管任务，不创建播放器或提前播放；下一题接管这个 Promise。退出页面、回顾、结束挑战或更换音源设置会取消预查请求，浏览器开启节省流量模式时不启动。播放器状态的 `data-load-ms` 与悬浮提示记录本题就绪耗时，便于抽测。

## 个人数据迁移

打开「设置 → 个人数据备份 → 导出完整备份」，妥善保存下载的 JSON。在另一浏览器或站点打开相同入口，选择文件、核对摘要，再点击「确认覆盖并恢复」。建议恢复前先导出目标浏览器的现有备份。

备份格式为 `anime-song-personal-backup` 版本1，最多5MB。白名单包含收藏、自定义歌曲、追番、音源反馈及状态、最近五局、成绩、题数、类型、预设或来源组合、音源偏好和音量；未设置项以null表示。不包含身份凭据、API Key、代理地址或媒体缓存。新备份不导出选歌/错题本；旧备份中的选歌仅供刷新后的追番迁移，错题本数据不恢复。新快照恢复会清除目标端残留的旧选歌键，避免错误重播迁移。字段错误不写入，写入失败回滚，恢复后刷新；无法保证浏览器进程突然退出时完成整个操作。

旧的自定义歌曲数组 JSON 导入保留番剧 ID、中文及原文名、季度、封面、导入来源和已确认音源。它只新增未重复的歌曲，不替换完整个人记录；未知字段不导入。

## API 与配置

| 入口 | 行为 |
|---|---|
| `/api/search?q=关键词` | B 站搜索，返回视频 ID、标题、作者、时长等 |
| `/api/search?bvid=BV…` | 取音频 CDN 地址，可能带备用地址。仅本地代理还有直链视频流回退 |
| `/api/search?stream=…&backup=…` | 转发允许的 HTTPS CDN 地址，保留字节范围，主地址失败时可试备用地址 |

前端配置在源码和浏览器设置中。YouTube 客户端 API Key 与 Firebase 配置可被浏览器查看，权限和配额依赖各平台控制台。Vercel 可选设置 `BILI_COOKIE` 供服务端请求使用。季度更新脚本可选设置 `YOUTUBE_API_KEY` 和 `BILI_WORKER_URL`。GitHub Actions 用工作流提供的令牌维护季度候选 PR。

## 季度更新

```sh
npm run discover -- --year 2026 --season fall --out candidates/2026-10
npm run update-season -- --year 2026 --season fall
```

发现脚本默认按 Bangumi 当季 TV 热度排序，按 AniList ID 关联 AnimeThemes，对热度前 30 名候选关联所有常规 OP、ED。缺少可靠资料时少收，不向低排名顺延补满；已有发布曲目继续保留。长篇作品可有 OP2、ED2 或更多曲目，季度总曲数随实际资料变化。AnimeThemes API 不可用时尝试读取官方季度页及番剧页的结构化主题曲记录。使用 `--rank-source anilist` 可显式选择旧的 AniList 排序入口。候选保存在 `candidates/YYYY-MM.json` 和同名 Markdown 中。季度键使用 01、04、07、10。发现命令默认用 UTC，Windows 更新入口默认用本机日期。

`一键更新季度曲库.bat` 默认按本机日期取当季。补查 10 月可在命令窗口运行 `一键更新季度曲库.bat --year 2026 --season fall`。交互脚本按 Bangumi 收藏热度选择当季 TV 动画，直接使用榜单中文名，以 AniList 和 AnimeThemes 补充封面及 OP／ED。

遇到无法确认的番剧或歌曲时，按窗口提示补填或跳过。输入 `/quit` 保存退出，下次继续。手工音源支持 YouTube 视频、B 站完整视频地址和 iTunes 试听直链。请先试听确认曲目，脚本会再检查链接可用性。候选进度与逐首报告在 `candidates/YYYY-MM-bangumi.*`。

B 站请粘贴浏览器地址栏中形如 `https://www.bilibili.com/video/BV…/` 的视频页。若复制到的是 `b23.tv` 分享短链，先用浏览器打开，再复制展开后的地址。可用 `--check-links 9` 抽查榜单前 9 部的音源，或用 `--retry-skipped` 把已跳过的番剧放回复核队列。

进入逐项复核前，脚本会批量检查当前候选。每次最多检查两首，每首的三个音源并行，快查上限 12 秒。扫描后可输入 `R` 重试失败项，已通过的结果会复用。更新代理文件后，重启已打开的本地 B 站代理窗口可使用新的线路规则。

完成可核实作品的逐曲复核后，输入 `Y` 才写入曲库、封面与音源，并更新浏览器缓存版本。失败会恢复这些文件。成功后刷新 8080 可查看新季度、海报和试听。YouTube 的自动检查依据嵌入状态，实际播放仍受地区、网络和授权限制。GitHub 工作流同样默认按 Bangumi 热度生成候选 PR。

批量历史归档工具 `npm run build-archive -- --cache 已复核资料目录` 先预览，添加 `--write` 才写入数据。输入目录需要 `match-plan.json`、季度 AniList 快照及已验证的 `anime-作品slug.json` 官方页面数据；该工具不会把缓存内未关联的作品当作已确认条目。维护记录在 `candidates/season-archive-manifest.json`，原有番剧档期及来源在 `candidates/legacy-quarter-archive.json`。


项目无构建、Lint 和 TypeScript 步骤。Vercel 从仓库根目录提供静态资源与 `api/search.js`。GitHub Pages 和其他纯静态托管仅提供网页，B 站功能使用网页设置中的代理地址。部署应包含三个数据模块、所有前端模块和图片。修改模块时更新其导入 URL 的缓存版本。校验脚本要求 `index.html` 的 CSS、入口脚本与 `app.js` 的原有曲库版本一致。

## 常见问题

- **页面空白或按钮没反应**。通过 HTTP 或 HTTPS 打开网页。Firebase SDK 只在进入联机或打开房间邀请时加载。
- **GitHub Pages 的 B 站音源**。打开设置，选择「智选三源」或「仅B站」，默认使用公开 HTTPS 代理。如果以前手动填写过代理地址，可清空地址后保存以恢复默认。更新公开代理代码后，需要另外部署 Vercel 项目。
- **音频等待过久**。单人题目首次搜索和自动换源共用 15 秒等待预算。等待时可点「换一首」，不计错题。
- **YouTube 提示点击播放或跳题**。浏览器可能拦截自动播放，视频也可能受嵌入或地区限制。可点播放或切换来源。
- **YouTube 一直准备播放器**。页面必须保留 `strict-origin-when-cross-origin` 来源策略，不能全局使用 `no-referrer`，否则 YouTube 可因缺少站点身份拒绝嵌入。播放器初始化统一等待最多 8 秒；连接失败后暂时避开 YouTube 60 秒，优先尝试所选模式允许的其他来源。「重新加载」或重新选择音源模式可主动重试。需要用户点击播放时会停止自动跳题计时，不会把自动播放权限问题记作歌曲失效。
- **YouTube 暂停后续播**。续播使用 `playVideo()` 保留位置，不再停掉共享播放器重新加载。答题片段按实际媒体进度结束，曲库试听使用 `endSeconds: 30`，暂停和缓冲不消耗片段时长。持续缓冲会超时换源。
- **iTunes 找不到正确的歌手**。搜索与评分共用已核实的歌手别名，目前包含泽野弘之、澤野弘之、SawanoHiroyuki[nZk]。仍会拒绝其他歌手的同名曲、翻唱及伴奏，后续按真实失败记录补充别名。
- **季度曲目难匹配**。部分曲名和歌手只有罗马音，外部搜索结果可能主要用日文。查看音源反馈和候选核查记录。
- **换浏览器后数据不见了**。本地记录按浏览器和站点来源保存。自定义曲库可用 JSON 迁移。
